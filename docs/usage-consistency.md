# 用量一致性与升级说明

关联 [Issue #211](https://github.com/juejin-cn/juejin-usage/issues/211)。

## 修复范围

- 队列按项目记录，而一个上传事件汇总同一时段、来源、collector、模型的全部项目。A=100、B=200 后仅 A 增至 150，云端应接收 350；冲销后的零桶也必须发送。
- 上传前保存待确认快照。仅合法的全量接受响应可直接确认；重复、部分接收和异常计数必须按稳定事件 ID 读回核对五类 Token、规范化会话数及显式费用。旧请求只能确认其实际发送值，上传期间的增长继续排队。
- 实时上传、后台补报和手动校准使用同一个持久化队列与锁。读回按时间范围分段，避开已知游标问题；返回时间可能有偏移，不用返回时间重建事件 ID，漏查不代表删除。
- 新补记追踪线程累计区间及原始桶。晚到明细只替代同一计数代次中可证明的重叠区间，其他新消耗不能抵扣旧补记。补记不会从 unknown 模型自动迁移。

## 升级和恢复

首次升级将产品统计窗口内的现有记录重新入队，即使旧版本已经保存了完整 hash。修复版本标记只表示已入队；每次启动仍会首次全量比对。服务端可接受窗口以外的数据保留等待，窗口扩大后可继续补报；仍沿用产品窗口的淘汰规则，不承诺窗口外全部历史数据最终接收。

Codex 在独立的 `codex-ledger-provenance.json` 中保存补记区间和历史基线；清解析游标、重扫及扩大范围不会自动减少历史基线。旧版补记缺少可追溯区间，作为“历史未核对”保留。不能证明重叠的记录不猜测扣减。

提交先写 `codex-ledger-pending.json`，包含最终桶快照、下一 Codex 游标和补记状态，再应用到队列。读取或采集前恢复未完成提交；重放完整快照，不重复减量。损坏恢复记录会报错并暂停，不能删除状态后当作空数据重新采集。备份或迁移数据目录时应一起保留队列、游标、上传状态和这两个文件。

## 显示与兼容

- 总费用仍为原有费率计算出的预估值，拆分为“明细预估”和“补记估算”，并标明补记 Token 与历史未核对 Token。
- 分类不完整时缓存率显示“明细不足”；旧云端缺少可选字段时显示“暂无拆分”，不能将未知当作零。
- 本地采集结果和云端上传结果分开：`upload.state` 为 `disabled`、`confirmed`、`pending` 或 `failed`，同时提供待处理数量、最近尝试和确认时间及原因。Desktop 从持久化状态读取，不改变 worker 消息协议。
- “云端已接收”只表示记录得到确认，不保证排行榜缓存已刷新。Web 排行榜在前台每 10 秒及重新获得焦点时刷新；隐藏、认证尚未完成或已有请求时跳过重复请求。
- 公网上传格式和模型费率保持兼容。新增拆分及状态字段都是可选的本地 API 元数据。

## 验证边界

回归使用脱敏的合成线程、项目与用量，所有云端写请求使用模拟服务。真实本地数据只在隔离副本中回放，不提交凭据、真实项目路径或聊天内容。手动删除式云端校准仍须用户显式操作，本修复不会自动调用。

修复可验证的一致性问题，不能还原缺失日志，也不宣称已修正全部历史消耗或实际账单。
